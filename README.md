# 翁法罗斯月历

使用当前文件夹 12 张月份海报与 1 张封面制作的原生 Android 日历。界面为中文，深色底配金色细节。应用本身无联网权限、广告或统计 SDK。

## 安装体验

1. 把 `dist/amphoreus-calendar-debug.apk` 传到 Android 8.0 或更高版本手机。
2. 在手机文件管理器中点击安装；按系统提示允许该文件管理器安装应用。
3. 打开「翁法罗斯月历」。首次打开会直接弹出系统日历权限请求，允许后会自动使用第一个可写日历。
4. 如果暂时拒绝授权，应用仍可使用本地日历；以后可在「设置 → 连接系统日历」恢复授权。
5. 选择要显示的日历和默认新建日历。创建日程时也可以选择保存位置。
6. 如果使用本地日程提醒，在设置中开启通知；需要准时提醒时开启精确提醒。

每次从图标启动会先随机显示一张开屏动画（共 13 张：昔涟年历封面 + 12 个月角色）：可在「设置 → 开屏动画」中选择参与随机的素材。开屏只显示角色插画和对应寄语，原海报下方的月份日历、标题与印刷文字会被裁掉；画面会做轻微推近、淡入和星尘流光，动画结束后自动进入月历主页，轻触画面可以提前进入。

这是首版测试安装包，使用项目专用调试签名，不是应用商店发行版。`.signing/debug.keystore` 保留在本机并被 Git 忽略；后续测试更新应保留这个签名文件，以便直接覆盖安装。卸载应用会删除本地日程。

## 使用方式

### 月历

- 首页上半是当月原版海报的插画区（**全宽铺满、零裁切**，常规手机上占屏高约 57%），底部以接近海报的衬线字体显示当月角色寄语；下半是应用自己计算的真实日期格，两者在同一页面里连成一张海报，不需要点开大图。
- 插画面板钉在日期格上方，翻日期不会把图滚走；插画与日期格之间用当月插画自己的底边色过渡，不是一条硬切的边。
- 高度由 `core/FitBudget` 按屏幕实际可用高度分配：常规手机零裁切；屏幕偏矮时插画让位，优先保证整月 6 行格子仍在首屏内。
- 每个月用自己的主题色：取自当月海报插画的主色（1 月门关月的暖红、4 月耕耘月的麦金、8 月收获月的青绿……），年月标题、日期格线、今天与选中状态都用它。
- 顶条左侧显示当前月份的翁法罗斯月名，例如 9 月为「拾线月」、10 月为「纷争月」；保留左右箭头，也可以在首页左右滑动翻月。
- 首页插画会播放低幅度的月度动效：不同月份分别使用余烬、星屑、轨道、花瓣、风、叶片、金色丝线或薄雾等透明叠层；原图不变形，离开首页后自动暂停。
- 日期格沿用海报下方那张印刷日期表的语言：直角、只有竖向分隔线、没有横向格线、衬线数字；主题色实心标识选中日、主题色描边标识今天、小圆点表示当天有日程，上／下月的日期淡化显示。
- 点击左右箭头翻月，点击「今天」回到当前日期；点击年月标题跳转日期。
- 点击日期查看当天日程，长按日期新建日程。

### 日程

- 底部「日程」可选择当天、本周、未来 30 天。
- 搜索框搜索当前范围中的标题、地点和备注。
- 支持标题、地点、备注、起止时间、全天、提醒，以及每天/每周/每月/每年重复。
- 全天事件的结束日期包含在内；保存到系统 Provider 时转换为结束日次日的 UTC 边界。
- 编辑或删除简单重复日程时作用于整个系列。
- 有复杂重复规则、例外、多个提醒或参会信息的系统事件，提供系统日历入口，保留原事件内容。

### 系统同步

应用直接读取 Android Calendar Provider，并直接向选定的可写系统日历保存事件。因此在手机的其他日历应用里可以看到变更，那些应用做出的修改也会在本应用刷新显示。

跨设备云同步由手机已有的账号同步服务负责，例如 Google、Exchange 或厂商账号。请先在手机系统日历添加账号，并开启该账号的日历同步。**保存到「本地日历」的日程只存在本应用中，不会自动复制到系统日历。**

只读日历可查看，不可编辑。拒绝权限后仍可使用本地日历；设置中提供恢复授权入口。系统日程的提醒由手机日历应用/服务发送，本应用不会再重复发送一次。

### 桌面小组件

- 长按手机桌面 → 小组件 → 翁法罗斯月历。
- **主题月历**：当月插画、数字月份与翁法罗斯月名、日期网格、今天/日程标记；支持独立翻月和日期跳转。插画优先：默认 5 格高，插画吃掉日期区以外的全部高度（约露 70%，拉到 4x6 是 90%，拉小到 4x4 约 40%）；插画位图固定为原图比例、视图用 centerCrop，所以画面只会被居中裁切，不会随卡片尺寸变化而拉伸变形。
- **今日安排**：左侧一竖条当月插画（角色头脚都在框里）、今天日期、未来 30 天内最近的安排，以及新建入口。
- **图文月历**：新增左右分栏卡片，一侧是当月角色插画，另一侧是可翻月、可点击日期的六行月历。
- 桌面小组件使用静态插画，避免持续动画刷新造成耗电；动态效果只在应用内首页播放。
- 添加时选择是否展示日程；以后点击齿轮修改。长按卡片可调整尺寸。
- 设置页提供「添加卡片」按钮，需手机启动器支持固定小组件接口；否则使用长按桌面方式。
- 主题月历声明最小高度 560dp（建议 4x6），最后一行显示今日安排；也可拉小到 4x5 只显示原有月历内容；图文月历建议至少 300×210dp；今日卡片默认 3 格高，拉高后会按空间展示更多安排，最多 6 条。启动器实际占用的格数可能与声明不同。
- 应用内修改立即刷新；系统日历变化触发后台刷新，另有系统半小时周期与日期变化更新兜底。省电模式下系统可能延后后台刷新。

### 插画与日期

13 张海报（年历封面 + 1–12 月）只作为插画来源：应用只取海报上方的插画区，海报下方印刷的 2026 日期表不参与显示，真实日期全部由应用按公历计算。原图固定属于 2026 年；正常日历页面可以使用其他年份，主题插画按月份复用。

每张海报的插画区底边与插画底边色由 `tools/calibrate_art.py` 从图里量出（12 张实测落在 0.5829–0.5874，逐月底色 12 个互异），写进 `Art.java` 的 `CALIBRATED` 标记块并同步 `docs/art-bounds.json`。换素材后重跑该脚本，不要手改常量：

```powershell
python tools/calibrate_art.py --check          # 校验 12 张的边界是否仍在预期区间
python tools/calibrate_art.py --write-java     # 把常量写回 Art.java 的标记块
```

## 构建

### 当前 Windows 环境的离线构建（已实际使用）

需要 JDK 17、Android SDK Platform 35、Build Tools 35.0.0。没有第三方运行库依赖，也不需要下载 Android Gradle 插件即可构建。

```powershell
.\scripts\build.ps1
.\scripts\test.ps1
.\scripts\startup-test.ps1 -Serial emulator-5556
```

`startup-test.ps1` 只应对测试模拟器运行，因为它会先撤销应用的日历权限来验证首次启动流程。

工具不在默认位置时：

```powershell
.\scripts\build.ps1 -Sdk 'D:\Android\Sdk' -Jdk 'D:\Java\jdk-17'
```

脚本执行 AAPT2 资源编译、Java 编译、D8 转换、zipalign、签名和签名校验，输出 `dist/amphoreus-calendar-debug.apk` 与 SHA-256。运行 `scripts/prepare-assets.ps1` 可从根目录重新复制原图。

### Android Studio / Gradle

用 Android Studio 打开本目录，配置 JDK 17 和本机 SDK，安装 API 35。工程使用 AGP 8.7.3 与 Gradle 8.10.2；首次 Gradle 同步需要联网下载依赖。

```powershell
$env:JAVA_HOME='C:\Program Files\Java\jdk-17'
.\gradlew.bat assembleDebug
```

本次 APK 通过离线 SDK 脚本生成；标准 Gradle 工程已包含，首次 Gradle 同步需要联网下载 Android Gradle Plugin。离线脚本和当前验证结果见 [docs/VALIDATION.md](docs/VALIDATION.md)。

### 设备集成测试

仅在测试模拟器上运行，脚本默认指定 `emulator-5556`。测试会创建并清理专用测试日历、写入测试事件，并授予测试需要的权限。

```powershell
.\scripts\build.ps1 -DeviceTests
# 或使用已构建的 APK
.\scripts\device-tests.ps1 -Serial emulator-5556
```

设备测试不包含真实账号的云端同步验证。测试专用 AppWidgetHost 位于 androidTest，不打包进用户应用。

### 首页版式核对（融合版式的自动化验收）

```powershell
.\scripts\verify-fusion.ps1                                            # 构建 + 安装 + 启动 + 截图 + 逐条断言
.\scripts\verify-fusion.ps1 -SkipBuild -Size 1080x1920,1440x3120       # 多尺寸回归
.\scripts\verify-fusion.ps1 -SkipBuild -AllMonths                      # 12 个月逐月核对 + 生成拼图
```

一条命令跑完：构建 → 安装 → 启动 → dump 视图树 → 截图 → 逐条断言。区域从视图树里取（`tools/view_tree.py`），
不是写死的像素，所以同一套断言能换分辨率重跑。核对内容与判据见 `tools/verify_screenshot.py` 的文件头与
`docs/VALIDATION.md`：插画面板与当月海报插画区段的归一化互相关、插画有没有被蒙版洗掉、接缝连续性、日期格
是否无圆角且竖线对齐列边界、整月是否在首屏内、日期是否为真实公历、逐月主题色、正文对比度。`-AllMonths`
会额外生成 `docs/screenshots/fusion-2026-MM.png` 与拼图 `fusion-contact-sheet.png`。

写入脚本时注意：`scripts/*.ps1` **必须保持纯 ASCII**。PowerShell 5.1 会把无 BOM 的脚本按 ANSI 读取，
非 ASCII 注释被解码坏之后语句会成片不执行——`verify-fusion.ps1` 就曾因此打印 PASS 而核对循环一次没跑。
`scripts/test.ps1` 现在会对 `scripts/*.ps1` 做 ASCII 校验。

## 源码结构

- `core`：日期格、事件实例、重复规则、提醒时间，独立于 Android。
- `data`：本地 SQLite、系统 Calendar Provider、统一查询入口。
- `ui`：月历/日程、日程编辑、设置；月历首页把海报插画与真实日期格画在同一页。
- `widget`：两个 AppWidgetProvider、配置和后台日历变化监听。
- `reminder`：AlarmManager、通知与重启/日期变化恢复。

详细需求和阶段安排见 [PLAN.md](PLAN.md)，素材映射见 [docs/ASSETS.md](docs/ASSETS.md)。

## 当前边界

首版未包含农历/节气、法定假日与调休、ICS 导入导出、重复事件单次例外编辑、参会邀请、独立 CalDAV/云账号服务。Android 8–14 及不同厂商手机的省电策略还需要真机兼容性测试。

本地通知权限、精确提醒权限和系统账号同步是否开启，会影响对应功能。正式发布前还需发行签名、商店资料、当时的 target SDK 适配，以及素材使用范围确认。
